# ate-controller reads only the egress MITM CA pool

## Change

The controller's Secret rule moves from its ClusterRole to its Role in the release namespace, on `egress-mitm-ca-pool` only (`resourceNames`, get, list and watch). The manager's cache already selects that Secret by `metadata.name`, so list and watch stay authorized.

## Reason

The controller reads one Secret, but its ClusterRole granted get, list and watch on every Secret in the cluster. On a management cluster that includes every workload cluster's admin kubeconfig.

## History

Cherry-pick of [agent-substrate/substrate#3036](https://github.com/agent-substrate/substrate/pull/3036) (merged 2026-10-22, `807652060`, part of #2936). The generated manifest conflicted with the line's copy, which already lacks the `events.k8s.io` rule; only the Secret rule move is applied there. The chart's `role.yaml` is regenerated by `hack/gen-rbac.sh`.

The line's chart rendered the controller's Role without a RoleBinding (kagent-dev/substrate's chart binds it since `cffc7c7bc`, [kagent-dev/substrate#97](https://github.com/kagent-dev/substrate/pull/97)), so the moved rule left the controller unable to list the pool: the chart e2e failed with `secrets "egress-mitm-ca-pool" is forbidden`. The RoleBinding is ported from that commit, and `manifests/ate-install/role.yaml` is regenerated with `hack/render-manifests.sh`. The binding also grants the Role's other rule, get, list and watch on EndpointSlices in the release namespace; the chart dials ateapi through `dns:///`, so that rule goes unused there.

The marker comment names `ctrl.Options in main.go`: upstream's `managerOptions` helper is not on the line, which builds the options inline.
