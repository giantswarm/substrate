# the upgrade entry rides in the pull request of the fix that cuts the patch

- **Status:** carried
- **Upstream:** not ours: the check names `docs/upgrade.md` and the line's release tooling, files of this line
- **Our commit:** [#404](https://github.com/giantswarm/substrate/pull/404)

## Change

`docs/dev/release-notes.md`, "Cut a release", states that the `docs/upgrade.md` entry of a patch rides in the pull request of the change that cuts it. The workflow `upgrade-entry` (`.github/scripts/upgrade-entry.sh`, with fixture runs in `upgrade-entry-test.sh`) fails a `feat`, `fix`, `perf`, `refactor` or `security` pull request against a line that leaves `docs/upgrade.md` alone, unless its description has a line `no-upgrade-entry: <reason>`.

## Reason

`cliff.toml` (generated by devctl, so not changed here) skips `docs`, `test` and `style` commits: a pull request that only adds the upgrade entry cuts no tag, and the next releasable commit ships the patch without it (v1.10.1-rc.1). Putting the entry in the releasable change's own pull request makes the tag carry it by construction, and the check makes that mechanical.
